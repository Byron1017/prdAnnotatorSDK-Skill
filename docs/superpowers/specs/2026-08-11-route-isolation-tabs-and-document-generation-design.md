# PRD Annotator 路由隔离、Drawer Tabs 与文档生成设计

日期：2026-08-11

状态：已批准

## 1. 背景与根因

PRD Annotator 当前把脚本上的 `data-page-id` 或 `location.pathname` 作为页面身份。对于 Vue 3 离线原型和 Hash Router，多个逻辑页面共享同一个物理 `index.html`，`pathname` 始终不变，因此这些页面共用同一个 localStorage 键、标注集合、页面 PRD 和 View 数据。

本次修改同时解决三个问题：

- 同一 HTML 中多个 Hash 路由的标注和页面文档互相串页。
- Drawer 把标注、页面 PRD 和所有文档纵向堆在一起，内容过长且难以定位。
- Skill 尚未完整规定：用户要求创建文档时，如何依照项目现有文档结构生成页面 PRD、字段规范或接口文档，并让 Drawer 展示生成结果。

## 2. 目标

- 每个逻辑页面都有独立、稳定、ASCII-only 且不超过 32 个字符的页面 ID。
- 同时兼容多 HTML、单 HTML Hash Router、动态路由、查询参数、普通锚点和直接打开深层路由。
- 页面切换时同步切换标注、Marker、localStorage、页面 PRD、关联文档和同步目标路径。
- 已经混合的旧标注永久保留，但不继续显示在任意路由的“本页标注”中。
- Drawer 采用五个 Tab，每次只展示一个内容区域。
- Skill 只在用户明确要求时创建或更新文档，并优先遵循项目现有目录、命名、模板和内容结构。
- 浏览器运行时继续保持纯本地、无保存服务、无 Python/Node 常驻进程。
- 继续保持恰好两个悬浮按钮。

## 3. 非目标

- 不根据 Vue 组件内部状态猜测逻辑页面。若页面切换不改变 URL 且没有显式页面键，SDK 将其视为同一页面。
- 不把普通文档锚点拆成页面。
- 不在安装、发现、标注同步或 View 刷新时自动创建或修改 PRD、字段规范或接口文档。
- 不自动判断、合并或覆盖多个含义不明确的候选文档。
- 不自动把旧版混合标注分配到某个新路由页面。
- 不增加第三个悬浮按钮，不引入本地保存服务。

## 4. 页面身份模型

### 4.1 组合身份

页面身份由下列信息组成：

```text
projectId + normalizedHtmlPath + optionalRoutePattern
```

- `projectId` 隔离不同项目。
- `normalizedHtmlPath` 隔离不同物理 HTML。
- `optionalRoutePattern` 只在已识别的 Hash Router 页面中区分逻辑页面。

因此，不同 HTML 即使具有相同 Hash 路由，也不会共享页面数据。

### 4.2 多 HTML 与无路由页面

普通 HTML、Vue 但未使用路由的页面以及没有已登记 Hash 路由的物理入口，继续以规范化的物理 HTML 路径作为页面身份。现有多 HTML 项目的页面 ID、数据文件和 View 文件保持有效。

示例：

```text
/prototype/index.html
/prototype/settings.html
```

二者始终是两个页面。

### 4.3 Hash Router 页面

Skill 从可用的 Vue Router 定义和项目源码中建立显式路由映射。一个物理 HTML 可以在 Manifest 中对应多个逻辑页面；这些页面共享 `htmlPath`，但拥有不同的页面 ID、路由模板、标注 JSON 和 View 文件。

示例：

```text
index.html + /message/manage
index.html + /message/template/edit/:id
```

二者是两个独立页面。

### 4.4 动态参数

运行时优先匹配路由映射中的模板。下列地址映射到同一个逻辑页面：

```text
#/message/template/edit/123
#/message/template/edit/456
```

其路由模板为：

```text
/message/template/edit/:id
```

动态值不进入页面 ID、文件名或 localStorage 键。

### 4.5 查询参数

Hash 路由中的查询参数不参与页面身份：

```text
#/message/manage?page=1
#/message/manage?page=2
```

二者属于同一个逻辑页面。

### 4.6 普通锚点

`#section`、`#form-title` 等普通文档锚点不参与页面身份。只有匹配显式路由映射的 Hash 路径，或者符合 `#/...` / `#!/...` 形式的未登记路由，才进入 Hash Router 处理流程。

### 4.7 直接打开深层路由

SDK 启动时必须先读取当前 Hash，再选择正确的逻辑页面和 View。不能先加载物理入口页的数据后再切换，否则会短暂显示或合并错误标注。

例如直接打开：

```text
file:///project/code/index.html#/message/template/edit/123
```

首次渲染即使用 `/message/template/edit/:id` 对应的页面数据。

### 4.8 未登记路由

当地址符合 Hash Router 形式但没有匹配任何路由模板时：

- 使用 `normalizedHtmlPath + normalizedHashPath` 生成短哈希隔离身份。
- 查询参数仍被忽略。
- 不加载物理入口页或其他逻辑页面的标注与 PRD。
- Drawer 显示“未登记路由，需要 AI Agent 刷新项目映射”的提示。
- 浏览器标注进入该隔离身份的 localStorage，避免数据串页。

Skill 后续刷新项目时可把该路由登记为永久页面；若路由可能包含动态参数但无法可靠识别，必须询问用户或保留隔离状态，不能猜测并合并。

## 5. Manifest 与生成资产

Manifest 中每个逻辑页面仍是独立页面条目。页面条目新增明确的身份描述，概念结构如下：

```json
{
  "id": "message-edit-31ab92",
  "title": "消息模板编辑",
  "htmlPath": "code/index.html",
  "identity": {
    "mode": "hash-route",
    "routePattern": "/message/template/edit/:id"
  },
  "annotationFile": ".prd-annotator/data/pages/message-edit-31ab92.json",
  "viewFile": ".prd-annotator/view/pages/message-edit-31ab92.js"
}
```

无路由页面使用 `identity.mode = "document"`。旧 Manifest 页面缺少 `identity` 时按 `document` 解释，以保持向后兼容。

每个物理 HTML 生成一个轻量路由注册资产，记录该入口允许匹配的路由模板、页面 ID 和 View 路径。HTML 仍只注入一个 SDK 脚本；脚本增加一个项目内相对路由注册路径。所有路径继续经过“解析结果必须位于项目根目录内”的门禁。

永久数据仍保持每个逻辑页面一份：

```text
.prd-annotator/data/pages/<page-id>.json
.prd-annotator/view/pages/<page-id>.js
```

## 6. SDK 导航与数据流

### 6.1 启动

1. 读取项目 ID、物理入口身份和路由注册资产。
2. 规范化 `pathname`、Hash 路径和查询参数。
3. 解析当前逻辑页面 ID。
4. 创建该页面专属 localStorage Store。
5. 只加载该页面的 View。
6. 合并同身份的浏览器缓存与永久 View 数据。
7. 渲染 Marker、同步状态和 Drawer。

### 6.2 导航监听

SDK 同时监听：

- `hashchange`
- `popstate`
- `history.pushState`
- `history.replaceState`

每次通知都重新解析完整位置，但只有逻辑页面 ID 发生变化时才执行页面切换。

### 6.3 页面切换

1. 保存当前页面缓存。
2. 关闭标注编辑器，退出标注模式并清除旧 Marker/高亮。
3. 解析下一页身份并切换 localStorage Store。
4. 清空当前内存中的页面 PRD和文档 View 状态。
5. 加载下一页缓存和 View；过期的异步 View 返回不得覆盖新页面。
6. Drawer 回到“本页标注”Tab并保持关闭状态。
7. 重新渲染下一页 Marker 和内容。

### 6.4 浏览器存储

localStorage 键继续使用 `projectId + pageId`。Hash 动态参数和查询参数不进入键名。页面切换绝不把当前文档状态保存到下一页的键。

同步快照和复制给 Agent 的完整载荷必须包含已解析的逻辑页面 ID、实际 Hash 路径、路由模板、物理 HTML 路径、标注文件路径和 View 文件路径。Agent 只能把载荷合并到同身份页面。

## 7. 旧数据保留与迁移

旧版本可能已经把多个 Hash 页面标注保存在物理入口页的 localStorage 或永久 JSON 中。由于 SDK 无法可靠判断每条标注来自哪个历史路由，升级时不得自动分配。

- 保留旧 localStorage 键，不清除、不覆盖。
- 保留旧永久 JSON 和 Manifest 历史记录。
- 将这部分数据标记为“未归类旧标注”。
- “本页标注”Tab不展示未归类旧标注。
- Drawer 可显示未归类数量和处理提示，但不得把内容伪装成本页数据。
- 只有用户明确要求并给出归属，或 AI 能从可靠证据确定归属且用户要求整理时，Skill 才迁移副本。
- 迁移前后必须校验标注 ID 数量和内容，原数据默认仍保留。

## 8. Drawer Tab 设计

Drawer 顶部继续显示当前页面标题、物理 HTML、当前路由、View 生成时间、同步状态和关闭按钮。其下使用吸顶 Tab 栏，替代当前全部内容纵向堆叠的布局。

Tab 固定为：

1. `本页标注`：仅展示当前逻辑页面标注，标题旁显示数量。
2. `页面 PRD`：展示当前逻辑页面关联的页面 PRD；没有内容时显示明确空状态。
3. `关联文档`：展示需求、流程、公共规则、总 PRD、其他相关或未分类资料。
4. `字段规范`：展示分类为字段、数据字典、数据模型或字段约束的文档。
5. `接口文档`：展示分类为 API、接口契约、请求响应或错误码的文档。

交互与可访问性要求：

- 默认选中“本页标注”。
- 同一时间只显示一个 Tab Panel。
- Tab 始终可见；空内容使用空状态，不隐藏 Tab。
- Tab 栏在 Drawer 内容滚动时吸顶。
- 窄屏允许 Tab 横向滚动，不压缩到无法识别。
- 使用 `tablist`、`tab`、`tabpanel`、`aria-selected`、`aria-controls`，支持方向键切换。
- 页面身份变化后重置到“本页标注”。
- Tab 选择只属于展示状态，不修改任何文档或标注数据。
- 同一文档可依据证据出现在多个相关 Tab；SDK 不合并、不覆盖、不替用户取舍。
- 所有文档继续显示来源路径、类型、预览状态和缺失/过期状态。

## 9. Skill 的路由发现与维护

Skill 在以下明确请求范围内建立或刷新路由映射：

- 用户授权安装 PRD Annotator。
- 用户要求修复、刷新或维护现有 PRD Annotator 集成。
- 用户明确要求升级 SDK/Skill 后执行兼容迁移。

Skill 优先检查 Vue Router 常见入口、路由数组、懒加载模块和嵌套路由。发现动态参数时保留声明的路由模板。不能可靠解析时，列出候选或保留未登记路由状态，不根据 URL 数字或字符串外观猜参数。

刷新路由映射时必须：

- 保留已有页面 ID、永久标注、手工路由映射和文档关联。
- 为新逻辑页面建立独立页面 ID、标注 JSON 和 View。
- 将已删除的历史路由标记为缺失或停用，而不是删除其数据。
- 验证每个物理 HTML 的路由注册路径和每个逻辑页面的 View 路径均位于项目内。
- 完成后运行项目门禁。

## 10. Skill 按用户要求生成文档

### 10.1 授权边界

Skill 只在用户明确表达创建、整理、补充或更新某类文档的意图时写文档。自然语言即可，不需要固定口令。

以下操作不构成文档生成授权：

- 安装 SDK。
- 浏览器中新增标注。
- 同步标注到永久 JSON。
- 刷新路由映射或 View。
- 仅查看 Drawer 中的文档。

因此，“同步本页标注”本身不得自动修改 PRD、字段规范或接口文档。

### 10.2 文档结构发现

收到文档工作请求后，Skill 必须先发现并读取：

- 项目现有文档根目录。
- 同类型文档的目录、文件命名和标题规则。
- Markdown/JSON/YAML 等已有格式。
- 章节层级、表格字段、接口模板、术语和编号方式。
- Manifest 中的文档资产清单和页面关联。
- 当前逻辑页面的永久标注 JSON。

选择规则：

- 用户明确指定路径或模板时，严格使用该结构。
- 只有一个同类型且含义明确的文档根或模板时，复用它。
- 多个目录、模板或目标均合理时，列出候选并询问，不能自行取舍或合并。
- 项目没有现有结构时，只有在用户明确要求创建对应文档后，才使用 Skill 默认结构。

### 10.3 支持的生成目标

根据用户请求，Skill 可以生成或更新：

- 页面 PRD：关联当前逻辑页面 ID，并在“页面 PRD”Tab 展示。
- 总 PRD或公共规则文档：作为关联文档展示；明确影响总体范围或跨页面流程时，按已有总 PRD规则更新。
- 字段规范、数据字典或数据模型文档：分类到“字段规范”Tab。
- 接口文档、API 契约、请求响应和错误码文档：分类到“接口文档”Tab。
- 其他需求、流程、验收或设计资料：分类到“关联文档”Tab。

用户一次要求多个文档时，可以在同一受控文档工作流中生成，但每个文件都必须有明确目标结构和页面/项目关联。

### 10.4 生成后的展示流程

1. 写入或更新用户授权的文档。
2. 更新 Manifest 文档条目的路径、标题、格式、类型、页面 ID、关联证据和内容指纹。
3. 不删除或隐藏其他候选文档。
4. 重新生成受影响页面的 View。
5. 运行路径、数据、文档和可再生成门禁。
6. 用户刷新原型后，文档出现在对应 Tab。
7. Agent 报告所有修改文件和文档变更摘要。

## 11. 错误处理

- 路由注册资产缺失或无法解析：使用隔离身份，不加载其他页面 View，并显示修复提示。
- 多个路由模板同时匹配：拒绝选择，显示映射冲突并要求 Agent 修复。
- View 加载竞态：每次页面切换使用身份令牌；旧页面异步结果必须丢弃。
- View 缺失或过期：浏览器标注仍可使用，文档 Tab 显示需要 Agent 刷新的状态。
- 动态路由无法可靠识别：保持未登记隔离，不猜测参数模板。
- localStorage 不可用：保留当前内存数据并显示阻断性同步提示。
- 文档目录或模板不明确：停止写文档并询问用户。
- 文档生成失败：保留现有文件和 Manifest，不能用部分生成结果报告成功。
- 旧标注无法确定归属：保留未归类状态，不自动迁移。

任何异常都不能导致删除标注、删除文档或把其他页面内容作为当前页内容展示。

## 12. 门禁

项目检查至少验证：

- 页面 ID 唯一、ASCII-only 且不超过 32 个字符。
- `document` 页面按物理 HTML 隔离。
- `hash-route` 页面以物理 HTML 与规范化路由模板组合隔离。
- 同一物理 HTML 的路由模板不存在冲突或重复。
- 所有 HTML、SDK、路由注册、标注和 View 路径均解析到项目根内。
- 每个逻辑页面有独立标注 JSON 和 View。
- 查询参数和动态值没有进入页面 ID 或文件名。
- 未登记路由不会加载其他页面数据。
- 旧数据仍存在且未被自动分配或删除。
- Drawer 保持恰好两个悬浮按钮和五个 Tab。
- Tab 文档分类与 Manifest 类型一致，所有候选文档仍可见。
- 标注同步没有修改任何 PRD、字段规范或接口文档。
- 每个新生成文档都有明确用户授权、目标结构和 Manifest 登记。
- Skill 管理的页面 PRD可以从结构化数据重新生成。
- Skill 管理的总 PRD索引全部已登记逻辑页面。

## 13. 测试策略

### 13.1 单元测试

- 规范化 Hash 路径、`#!/`、尾斜杠和编码字符。
- 忽略 Hash 查询参数。
- 普通 `#section` 不触发页面切换。
- 动态路由模板匹配与优先级。
- 未登记 Hash 路由生成隔离短 ID。
- `hashchange`、`popstate`、`pushState` 和 `replaceState` 通知。
- 同一 HTML 不同路由的 localStorage 键隔离。
- 不同 HTML 相同 Hash 的身份隔离。
- View 竞态返回不会覆盖当前页。
- Tab 默认状态、键盘操作、空状态和页面切换重置。
- 文档类型到 Tab 的分类；同一文档允许多分类。
- 标注同步与文档生成授权严格分离。
- 文档结构发现、单一模板复用、多候选阻断和 Manifest 更新。
- 旧缓存和永久 JSON 保留且不进入本页标注。

### 13.2 端到端测试

- 一个 Vue 风格 `index.html` 中的两个静态 Hash 路由，标注、Marker、PRD和文档完全隔离。
- 动态地址 `/edit/123` 与 `/edit/456` 使用同一逻辑页面。
- 查询参数变化不切换页面。
- 普通锚点变化不切换页面。
- 直接打开深层 Hash 路由首次渲染即加载正确页面。
- 未登记路由不显示入口页或其他路由标注。
- 两个不同 HTML 即使 Hash 相同仍完全隔离。
- 无路由 Vue 页面和普通多 HTML 项目保持原行为。
- 快速连续路由切换不会被旧 View 回写。
- 五个 Tab 每次只显示一个 Panel，窄屏可用，恰好两个悬浮按钮。
- 用户授权生成页面 PRD、字段规范和接口文档后，刷新 View 即分别出现在对应 Tab。
- 仅同步标注时，所有文档字节保持不变。
- 升级前混合标注仍可恢复，但不显示为任一路由的本页标注。

### 13.3 完整回归

修改必须通过现有全部单元测试、Playwright E2E、构建、Release 打包、Skill 校验、Fixture 门禁和仓库路径扫描。实现阶段先提交失败的回归测试，再编写修复代码。

## 14. 验收标准

- “消息模板编辑”产生的标注不会出现在“消息管理”的本页标注中。
- 同一 `index.html` 下的每个已登记 Hash 路由拥有独立永久数据和页面 PRD。
- 多 HTML 和无路由项目不受 Hash 支持影响。
- 动态参数被模板化，查询参数和普通锚点不制造新页面。
- 深层路由直接打开时不闪现、不合并错误页面数据。
