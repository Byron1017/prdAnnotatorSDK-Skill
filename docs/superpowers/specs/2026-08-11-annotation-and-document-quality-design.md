# PRD Annotator 标注精简与文档质量增强设计

## 背景

PRD Annotator 当前同时暴露了两个独立问题：

1. 标注表单字段过多，Drawer 中的标注卡片层级混乱，历史字段占用大量空间。
2. 页面 PRD、关联文档、字段规范和接口文档的 Markdown 展示能力不足。现有渲染器不支持 GFM 表格、行内代码、强调和链接，导致表格源码被当成普通段落显示，文档生成也缺少稳定的结构与质量规范。

本次设计同时解决两个问题，但必须保持严格边界：标注能力与文档生成能力是两条独立工作线。三个外部参考 Skill 只用于增强 AI Agent 的文档生成和格式处理能力，不参与标注创建、编辑、删除、同步、存储、指纹或门禁。

## 目标

- 将新标注表单精简为标题、说明、类型、PRD 内容和备注。
- 保持 schema v2，兼容并永久保留历史标注字段。
- 将本页标注改成紧凑、清晰的分区卡片。
- 为 Drawer 增加安全、可读的 Markdown 表格和常用行内格式。
- 为页面 PRD、总 PRD、字段规范和接口文档建立独立、按需加载的写作规范。
- 借鉴三个外部 Skill 的通用工作流和质量规则，同时保持 PRD Annotator 的授权、路径和文档选择门禁。
- 保证 AI 只有在用户明确要求文档工作时才创建或更新文档。

## 非目标

- 不让外部参考 Skill 决定或改变任何标注字段。
- 不从标注同步自动触发页面 PRD、总 PRD、字段规范或接口文档修改。
- 不将三个外部 Skill 作为运行时依赖，也不要求用户另行安装。
- 不复制无明确许可证仓库的完整模板或大段原文。
- 不自动合并多个候选 PRD，不替用户选择有歧义的文档或模板。
- 不在本次增加 DOCX、PDF、OpenAPI、图表生成或代码反向生成能力；只有用户明确要求时，才可在未来独立设计。
- 不升级 `schemaVersion`。

## 强边界

系统分为两个相互独立的工作线。

### 工作线 A：标注运行时与数据

负责：

- 浏览器中的标注创建、编辑、删除和目标定位。
- 页面级 localStorage、快照、复制同步提示词和永久 JSON 合并。
- `note` 字段兼容、历史字段保留、标注指纹和标注门禁。
- 本页标注卡片、标记圆点和关联章节显示。

该工作线不得读取或应用三个外部参考 Skill 的规则。外部 Skill 不得改变标注表单、标注 schema、同步策略、删除墓碑、路由隔离或标注校验。

### 工作线 B：AI 文档生成与展示

负责：

- 用户明确要求时，创建或更新页面 PRD、总 PRD、字段规范或接口文档。
- 选择已有项目文档和模板，或在没有既有规范时使用内置回退规范。
- 检查文档结构、事实来源、逻辑一致性、格式和可读性。
- AI 写入文档后刷新 Manifest 文档清单和 View bundle，使 Drawer 展示最新内容。
- 在 Drawer 中安全渲染 Markdown。

三个外部参考 Skill 只影响该工作线的文档写作方法和格式。它们不读写标注数据。

### 唯一连接点

两条工作线只通过现有只读证据和展示刷新连接：

1. AI 在获得独立文档工作授权后，可以把同步后的本页标注 JSON 作为文档证据之一读取。
2. AI 完成文档写入后运行 `refresh-project.mjs`，把文档预览更新到 Drawer。

文档生成不得反向修改标注 JSON。View 刷新只更新生成的展示数据，不修改浏览器标注或永久标注内容。

## 采用的整合方式

采用“PRD Annotator 自包含文档参考层”。不把三个仓库作为依赖，不在运行时调用其 Skill，而是把经适配的通用规则写入 `prd-annotator-skill/references/`。

未采用的方案：

- 多 Skill 运行时编排：要求每台机器安装四个 Skill，触发和版本不可控。
- 直接复制第三方模板：内容过重，也不适用于无明确许可证的来源。

自包含方案保持全局 Skill 可独立安装、离线使用和版本化，并允许 PRD Annotator 自己执行授权与路径门禁。

### prd-skill

采用：

- 不确定的业务取舍不得由 AI 静默决定。

调整：

- 不强制页面 PRD 使用完整三阶段大 PRD。
- 不强制每个页面填写 NSM、商业定价、路线图或固定数量的指标。
- 页面级小改动使用轻量文档；跨页面或总体需求才使用完整结构。
- 验收和可验证性是正式文档质量要求，不重新成为标注表单字段。

该仓库采用 MIT License。实现仍以重新编写、适配后的简洁规则为主。

### document-specialist-skill

采用：

- 先识别文档用途、受众和类型，再加载对应规范。
- 标题、版本、范围、术语、链接、代码块和表格的一致性检查。
- 接口文档中的基础路径、鉴权、接口目录、请求、响应、错误和示例检查。
- 只加载当前文档类型所需的参考，避免 Skill 上下文膨胀。

调整：

- 不引入代码反向生成、DOCX/PDF 转换、教程、运维手册或复杂图表工作流。
- 不自动生成完整 OpenAPI；产品接口文档和研发 OpenAPI 保持不同文档类型。
- 不要求所有文档都包含作者、版本、术语表等与项目现有规范冲突的固定章节。

该仓库未发现独立许可证，因此只吸收通用质量规则，不复制模板原文。

## 文档授权与事实来源

文档工作继续执行现有 `prd-workflow.md` 的授权边界：

1. 只有用户明确要求创建、整理、生成、补充或更新某类文档时才允许写文档。
2. 使用用户明确指定的目标。
3. 没有明确目标时，只能使用唯一无歧义的同类文档。
4. 多个目标、模板或文档根合理时，列出标题、路径、类型和证据并询问。
5. 不合并、不删除、不移动未选中的候选文档。

文档事实优先级为：

1. 用户当前明确要求和已确认决策。
2. 用户确认的原型页面、逻辑路由和交互行为。
3. 已同步到永久 JSON 的本页标注；浏览器未同步内容不能被报告为项目事实。
4. 用户选定的现有页面 PRD、总 PRD、字段规范或接口文档。
5. 项目代码、配置或接口中的可验证事实。

证据冲突时不得静默选择。对文档目标有实质影响的冲突必须列为待确认事项或询问用户。

## 文档生成工作流

用户授权文档工作后，AI 应：

1. 读取当前逻辑页面 JSON 和 Manifest 关联的文档清单。
2. 检查相关原型 HTML、路由、页面状态和选中的现有文档。
3. 确认本次文档类型、目标文件和范围。
4. 使用项目现有唯一模板、标题层级、术语和目录结构；无现有规范时才使用对应回退参考。
5. 先整理事实、假设、冲突和缺口，再编写 Markdown。
6. 只修改用户授权的文档。页面影响只修改页面 PRD；公共规则、跨页面流程或总体范围在总 PRD 已明确时才同步更新总 PRD。
7. 对多个合理总 PRD 候选停止并询问。
8. 执行文档结构和 Markdown 可读性检查。
9. 运行 `refresh-project.mjs` 和 `check-project.mjs`。
10. 报告修改文件、内容摘要、总 PRD 联动和剩余待确认事项。

## 页面 PRD 回退规范

页面 PRD 以页面和逻辑路由为范围，建议包含：

1. 页面目标与范围。
2. 页面入口、路由、角色和权限。
3. 页面区域、关键信息和主要操作。
4. 主流程、分支流程、异常流程和返回行为。
5. 加载、空、错误、成功、禁用和权限状态。
6. 页面业务规则。
7. 与本页标注的追溯关系。
8. 字段规范和接口文档引用。
9. 风险、依赖和待确认事项。

页面 PRD 不强制包含无证据的商业指标、定价、路线图或发布日期。局部改动只描述现状、目标表现、影响范围和不影响范围。

## 总 PRD 回退规范

总 PRD 建议包含：

1. 产品目标、总体范围和非目标。
2. 页面索引，覆盖 Manifest 中所有目标页面。
3. 跨页面主流程和角色关系。
4. 公共业务规则、权限、状态和术语。
5. 页面 PRD、字段规范和接口文档索引。
6. 依赖、风险和待确认事项。
7. 必要的变更摘要。

页面 PRD 的普通局部变化不得自动修改总 PRD。只有用户已授权文档更新，并且影响公共规则、跨页面流程或总体范围时才联动。

## 字段规范回退规范

字段规范按业务对象、页面区域或表单分组。简单字段使用短表格，推荐列为：

| 字段 | 类型 | 必填 | 来源 | 约束 | 说明 |
|---|---|---|---|---|---|

规则：

- 字段名、枚举值和路径使用行内代码。
- 表格单元格保持简短；长约束拆成字段详情或业务规则。
- 不用一个超宽表格承载多段描述。
- 明确显示、编辑、默认值、空值和权限规则时，只记录有证据的内容。
- 不猜测数据库列、字段长度、数据类型或枚举值；缺少证据标为待确认。

## 接口文档回退规范

默认生成产品接口需求文档，不冒充研发 OpenAPI。建议包含：

1. 接口目的、范围、调用方、被调用方、基础路径和鉴权。
2. 简洁接口目录，推荐只包含方法、路径、用途。
3. 每个接口独立章节。
4. 请求参数、返回字段和业务规则。
5. 请求与响应示例代码块。
6. 错误场景、权限、安全、频控和审计要求。
7. 依赖、非目标和待确认事项。

未知的路径、鉴权、状态码、字段或错误结构不得补造。只有用户明确要求研发 OpenAPI 时，才进入独立的 OpenAPI 工作流。

## Markdown 写作规范

- 标题从一个 `#` 文档标题开始，正文按层级递增，不跳级。
- 一张表只表达一类映射；长段落不放入表格。
- 表格尽量控制在三至六列。
- 字段名、接口路径、HTTP 方法、文件路径和枚举值使用行内代码。
- JSON、YAML、请求、响应和流程示例使用带语言标识的代码块。
- 内部文档使用可解析的相对链接，禁止 `file://` 和超出项目根的路径。
- 列表项保持同一语法结构。
- 没有内容的章节不输出空表格或占位符；不确定内容进入待确认事项。
- 文档中的事实、假设和待确认事项必须可区分。

## Markdown Drawer 渲染

现有安全 DOM 渲染器扩展为安全 Markdown 子集，新增：

- GFM 表格。
- 行内代码。
- 粗体和斜体。
- Markdown 链接。

继续支持标题、普通列表、有序列表、引用、分隔线和代码块。

安全约束：

- 继续通过 DOM API 创建节点，不将源 Markdown 赋给 `innerHTML`。
- 不渲染原始 HTML。
- 链接仅允许相对项目路径、页内锚点、`http:`、`https:` 和 `mailto:`。
- 禁止 `javascript:`、`data:`、`file:` 和其他未知协议。
- 外部链接使用 `target="_blank"` 和 `rel="noopener noreferrer"`。

表格用语义化 `table` 渲染，并包裹在横向滚动容器中。样式包含清晰表头、边框、斑马纹、适当内边距和顶部对齐。字段名、HTTP 方法和短路径尽量不换行，长说明允许换行。

## 标注表单精简

新建和编辑表单只显示：

- 标题，必填。
- 说明，必填。
- 类型，必填。
- PRD 内容，必填。
- 备注，可选。

`status`、`target`、时间戳和 `prd` 关联信息继续由运行时维护，不成为本次新增的表单字段。

## schema v2 兼容

继续使用 `schemaVersion: 2`。新增可选字符串字段 `note`。

### 新标注

- 总是写入 `note`，未填写时保存为 `""`。
- 不再创建 `acceptanceCriteria`、`dataFields`、`apiPath` 或 `edgeCases`。
- 继续创建内部状态、目标、时间戳和 PRD 关联结构。

### 历史标注

- 历史标注可以没有 `note`。
- 如果历史标注已有四个旧字段，JSON、localStorage、快照、View 和同步必须原样保留。
- 标准化不得为了兼容而给原本没有旧字段的新标注补写空旧字段。
- 旧字段存在时必须是字符串，但不再推荐也不再要求生成。

### 编辑合并

编辑历史标注时，只更新：

- `title`
- `description`
- `type`
- `prdContent`
- `note`
- `updatedAt`

保留 `id`、`createdAt`、`target`、`status`、完整 `prd` 对象、四个旧字段和未知兼容字段。编辑不得把未显示字段覆盖为空或删除。

### 指纹与同步

`note` 位于 annotation 对象内，因此自然参与现有 annotation 指纹。localStorage、快照、复制提示词、永久 JSON、View 和 Agent 合并都必须保留它。备注变化应使同步状态变为未同步。

标注同步只写标注 JSON 和生成的 View；不会因为 `note` 或其他标注内容修改文档。

## 标注门禁

每条活动标注继续要求：

- 非空 ID、标题、说明和 PRD 内容。
- 合法类型、状态和影响范围。
- 有效创建时间和更新时间。
- 包含关联元素的目标恢复信号。

`note` 可缺省；存在时必须是字符串。四个历史字段可缺省；存在时必须是字符串。门禁不得要求新标注生成旧字段。

## 标注卡片

本页标注使用紧凑分区卡片：

- 顶部：稳定编号、标题、类型、状态、编辑和删除。
- 内容分区：说明、PRD 内容、备注、关联 PRD 章节。
- 空备注和空关联章节不渲染。
- 四个历史字段不再在 Drawer 中显示，但仍保留在数据中。

将卡片选择器从 `.annotation-list li` 限制为 `.annotation-list > li`，避免嵌套的 `.linked-sections li` 继承卡片网格而逐字换行。

## 错误处理

- Markdown 表格语法不完整时按普通段落处理，不丢失源内容。
- 不安全链接显示为普通文本或无链接文本，不抛出整个文档。
- 文档预览缺失或过期时继续显示现有 stale/missing 警告。
- 有歧义的文档目标、模板或文档根停止写入并询问。
- 文档生成缺少业务事实时使用待确认事项，不编造内容。
- 历史标注字段类型非法时门禁失败并报告具体标注，不自动清空。

- 历史标注旧字段在读取、编辑、缓存、快照、合并和 View 中保持不变。
- 编辑只合并五个表单字段并保留未知兼容字段。
- 备注变化改变指纹和同步状态。
- 门禁接受可选历史字段并拒绝非字符串值。

- 编辑器只显示五个字段。
- Drawer 卡片按分区显示说明、PRD 内容、备注和关联章节。

- 正确渲染表头、表体、行内代码、粗体、斜体和安全链接。

### 文档规范与 Skill 测试
